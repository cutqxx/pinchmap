# Дизайн-бриф pinchmap

Режим: **существующая система**. Своей дизайн-системы у плагина нет: весь внешний вид строится на CSS-переменных темы Obsidian в `styles.css`. Собственные стили и пресеты отложены до фазы 5. Задача брифа — описать то, что уже есть, и минимально продолжить эти правила для новых элементов фазы 2 «Богатые ноды», ничего не придумывая поверх.

Целевые платформы: iPad/iPhone (пальцы, Pencil, экранная клавиатура) и ПК (мышь, тачпад, клавиатура); светлая и тёмная темы Obsidian, а также сторонние темы.

---

## 1. Принципы, которые уже действуют (не менять)

1. **Никаких своих цветов.** Все цвета берутся из переменных Obsidian (`--background-*`, `--text-*`, `--interactive-accent`, `--color-*`). Хардкодить hex/rgb нельзя. Единственное производное значение — `color-mix(in srgb, var(--interactive-accent) 15%, transparent)` у рамки выделения.
2. **Префикс `pinchmap-`** у всех классов. Состояния — классы `is-*` (`is-root`, `is-selected`, `is-editing`, `is-hidden`, `is-left`, `is-child`, `is-sibling`) и `has-*` (`has-collapse-toggle`). Модификатор BEM встречается один раз (`pinchmap-node--drop-target`); новые состояния делать через `is-*`.
3. **Фолбэки у переменных**, которые бывают не во всех темах: `var(--font-text-size, 16px)`, `var(--font-semibold, 600)`, `var(--layer-popover, 50)`, `var(--size-4-3, 12px)`.
4. **Зона касания 44×44 px на экране при любом зуме.** Элементы управления внутри мира карты компенсируют зум через `transform: scale(calc(1 / var(--pinchmap-zoom, 1)))` с подходящим `transform-origin`. Видимая метка внутри меньше (22 px у «+», 18 px у счётчика свёртывания).
5. **Элементы управления вне мира карты** (панель «Готово», кнопки истории) имеют `min-width/min-height: 44px` и не масштабируются.
6. **Подписи через `aria-label`** с текстом из i18n (`t(key)`, en/ru) — так сделаны кнопки «+» и индикатор свёртывания.
7. **Фокус:** у канваса outline убран только для `:focus:not(:focus-visible)`; при фокусе с клавиатуры обводка остаётся. Выделение и цель перетаскивания — `outline: 2px` (сплошная / пунктир) `var(--interactive-accent)` с `outline-offset: 2px`, то есть состояние передаётся не только цветом, но и формой линии.
8. **Канвас без выделения текста** (`user-select: none`, `-webkit-touch-callout: none`, `touch-action: none`). Выделение текста разрешено только в поле ввода.

## 2. Токены и значения, которые уже есть

### Цвета (только переменные Obsidian)

| Назначение | Переменная |
|---|---|
| Фон канваса | `--background-primary` |
| Фон ноды, панели «Готово» | `--background-secondary` |
| Рамка ноды, разделители | `--background-modifier-border` |
| Подсветка цели перетаскивания | `--background-modifier-hover` |
| Текст ноды | `--text-normal` |
| Вторичный текст (счётчик) | `--text-muted` |
| Связи | `--text-faint` |
| Акцент (выделение, root, «+», «Готово», ввод) | `--interactive-accent` |
| Текст на акценте | `--text-on-accent` |
| Цвета веток | `--color-red/orange/yellow/green/cyan/purple` через `--pinchmap-color` |

### Типографика

- Размер: `var(--font-text-size, 16px)`; у root ×1.25 и `font-weight: var(--font-semibold, 600)`.
- `line-height: 1.5`. Шрифт наследуется из темы, свой не задаётся.
- Мелкий текст служебных меток: 11 px (счётчик), 16 px (знак «+»).

### Размеры и отступы

- Своей шкалы отступов нет; используются локальные переменные ноды и значения Obsidian.
- Нода: `--pinchmap-node-padding-block: 6px`, `--pinchmap-node-padding-inline: 10px`, `max-width: 300px`, `min-width: 2em`, `min-height: calc(1.5em + 2 * padding-block)`, `width: max-content`.
- Скругления: `var(--radius-m)` у ноды и поля ввода; `50%` / `9px` у круглых меток.
- Рамка: 1 px (root — 2 px), обводки состояний — 2 px.
- Отступ панели: `var(--size-4-3, 12px)`.

### Слои

- Выделенная нода и цель перетаскивания: `z-index: 1` внутри мира.
- Плавающий интерфейс поверх вида (панель «Готово»): `position: fixed; z-index: var(--layer-popover, 50)`.

### Анимации

В `styles.css` переходов и анимаций нет. Обработки `prefers-reduced-motion` тоже нет, потому что пока нечего отключать.

## 3. Компоненты фазы 1 (для справки)

`pinchmap-canvas` → `pinchmap-world` (transform камеры) → `pinchmap-edges` (SVG, `pointer-events: none`) + `pinchmap-node` (`span.pinchmap-node-text`; при редактировании — `textarea.pinchmap-node-input` поверх, `inset: 0`), дочерние `pinchmap-add-button.is-child/.is-sibling`, `pinchmap-collapse-toggle > pinchmap-collapse-mark`. Вне мира: `pinchmap-done-bar > pinchmap-done-button`, `pinchmap-marquee`, `view-action.pinchmap-history-action`. Меню — нативный `Menu` Obsidian через `showObsidianMenu`.

## 4. Фаза 2: как продолжить систему

Ниже ограничения для новых элементов. Они выведены из правил раздела 1, новых токенов не вводят. Пункты, по которым нужно решение разработчика, вынесены в раздел 5 и **не считаются решёнными**.

### 4.1 Отрендеренный Markdown внутри ноды

- Контейнер рендера — внутри `.pinchmap-node-text` (или его замены). HTML отдаёт `MarkdownRenderer` Obsidian, поэтому стили темы для `strong`, `em`, `code`, `a.internal-link`, `a.external-link`, `a.tag`, `img` применяются автоматически. **Перекрашивать их не нужно**: пусть выглядят как в заметках.
- **Сброс внутри ноды** (только то, что ломает компактную ноду):
  - `margin: 0` у `p`, `ul`, `ol`, `blockquote`, `pre`, `h1–h6` и у первого/последнего дочернего элемента — иначе нода раздувается от отступов абзацев.
  - Для отрендеренного HTML снять `white-space: pre-wrap` (переносы строк даёт сам Markdown). Сырой текст и `textarea` сохраняют `pre-wrap`.
  - `overflow-wrap: anywhere` (или `break-word`, как сейчас) для длинных URL и `code`, чтобы они не выходили за `max-width: 300px`.
  - `pre`/код-блоки: `white-space: pre-wrap` и `overflow: hidden`; горизонтального скролла внутри ноды быть не должно, он конфликтует с жестами канваса.
  - Заголовки внутри ноды не должны получать размеры h1 из темы: `font-size: inherit` с весом `var(--font-semibold, 600)` — так же, как root передаёт иерархию весом. (Если разработчик хочет сохранить размеры заголовков темы — см. раздел 5.)
- **Ссылки и теги в ноде не интерактивны.** `pointer-events: none` на `a`, `.tag` и `img` внутри рендера, чтобы тап попадал в ноду (выбор/бабл), а не открывал ссылку и не запускал поиск тега. Цвет ссылки из темы остаётся визуальной подсказкой.
- Для ноды с рендером `-webkit-touch-callout: none` и `user-select: none` сохраняются, как у канваса: долгое нажатие на картинку не должно открывать системное меню iOS.
- Состояние «рендер ещё не готов» не показывать отдельным индикатором: до завершения асинхронного рендера в ноде виден сырой текст (fast path), без мерцания и без спиннеров.

### 4.2 Иконка ссылки

- Иконка — SVG Lucide через `setIcon` Obsidian (в теме уже есть набор, эмодзи не использовать). Кандидаты: `link` или `external-link`; один или два значка — см. раздел 5.
- Видимый размер значка — 14–16 px, цвет `--text-muted`, при наведении `--text-normal` (так же, как `pinchmap-collapse-mark` реагирует на hover). На акцентном/цветном фоне не ставить.
- Если по иконке можно тапать, это отдельная цель попадания (`link-icon`) с зоной **44×44 px на экране**: та же схема, что у `pinchmap-add-button`/`pinchmap-collapse-toggle` (`width/height: 44px`, отрицательный margin на половину, `transform: scale(calc(1 / var(--pinchmap-zoom, 1)))`, `cursor: pointer`). Зона не должна перекрывать «+» и индикатор свёртывания: правая середина занята `is-child`/свёрткой, нижняя середина — `is-sibling`.
- `aria-label` из i18n (например, «Ссылка» / «Link»), `role="button"`.
- Иконка не должна менять размер ноды неожиданно: место под неё учитывается при измерении ноды или иконка размещена абсолютно поверх/снаружи рамки (см. раздел 5).

### 4.3 Бабл ссылки

- Плавающий элемент по образцу `pinchmap-done-bar`: `position: fixed` (или absolute в канвасе, но экранного размера — без масштабирования зумом), `z-index: var(--layer-popover, 50)`, `background-color: var(--background-secondary)` или `--background-primary`, `border: 1px solid var(--background-modifier-border)`, `border-radius: var(--radius-m)`, тень — `var(--shadow-s)` из темы (своих теней не вводить).
- Содержимое: кнопка «Открыть ссылку» (текст из i18n). Кнопка — `min-width/min-height: 44px`, цвет текста `--interactive-accent`, `font-weight: var(--font-semibold, 600)`, прозрачный фон — как `pinchmap-done-button`. Иконка Lucide рядом с текстом допустима, но текст обязателен (не только иконка).
- Если в ноде несколько ссылок — список кнопок, у каждой подпись с целью ссылки (имя заметки или домен), обрезанная `text-overflow: ellipsis`, `max-width` бабла ≈ 300 px (совпадает с нодой). Вики-ссылку и внешнюю различать значком, а не только цветом.
- Позиция: рядом с нодой (над ней, при нехватке места — под ней), следует за панорамированием и зумом, закрывается при любом другом намерении (тап по канвасу, начало редактирования, перетаскивание, Esc).
- Фокус: при открытии с клавиатуры фокус переходит на первую кнопку; видимая обводка фокуса (`:focus-visible`) не убирается. Esc закрывает и возвращает фокус на канвас.
- Без анимации появления либо короткая (150–200 мс, `opacity`), выключаемая при `prefers-reduced-motion: reduce`. Это будет первое правило `prefers-reduced-motion` в `styles.css`.

### 4.4 Миниатюры картинок в ноде

- Картинка вписывается в ширину ноды: `max-width: 100%` (то есть не шире 300 px минус отступы), `height: auto`, ограничение по высоте и `object-fit: contain`, чтобы высокие фото не растягивали ветку (точное значение — раздел 5).
- `border-radius: var(--radius-s)`, `display: block`, отступ от текста — `var(--pinchmap-node-padding-block)` (6 px), чтобы не вводить новое значение.
- Пока картинка грузится, место зарезервировано (если известны размеры) или нода перемеряется после `load`; нода не должна «прыгать» под пальцем во время жеста.
- Битая/отсутствующая картинка: вывод Obsidian по умолчанию (имя файла как текст/ссылка), без своего оформления ошибки.
- `alt` — из Markdown (`![[img.png|alt]]`) или имя файла; картинки не интерактивны (`pointer-events: none`), `draggable="false"`.
- Тёмная тема: фон под прозрачными PNG не задавать — нода уже имеет `--background-secondary`.

### 4.5 Точка вставки картинки

- Используются существующие паттерны, новых плавающих панелей не вводить без решения разработчика: пункт контекстного меню ноды (нативное `Menu`, иконка Lucide `image`) и/или кнопка в панели над клавиатурой во время редактирования (`pinchmap-done-bar`, кнопка 44×44 px, иконка + `aria-label`). Выбор — раздел 5.
- Выбор источника («Из хранилища» / «Из галереи или файла» / «Из буфера») — нативное `Menu` или `FuzzySuggestModal` Obsidian для хранилища; галерея — системный `<input type="file" accept="image/*">`, без своего UI.
- Вставка из буфера в поле ввода (событие `paste`) не требует отдельного UI.
- Сообщения об ошибках (слишком большой файл, нет доступа к буферу) — через `notify` (Notice Obsidian), текст из i18n.

### 4.6 Состояния ноды с богатым содержимым

- Выделение, цель перетаскивания, цвет ветки, root — без изменений: те же outline/border.
- При редактировании (`is-editing`) рендер скрыт так же, как сейчас скрыт `pinchmap-node-text`, а поле ввода показывает сырой Markdown. Смена режима меняет размер ноды — это ожидаемо, перемер обязателен.

## 5. Открытые вопросы к разработчику

Инструмент вопросов (AskUserQuestion) в этом запуске недоступен, поэтому по этим пунктам решения **не приняты**. Их нужно закрыть до спецификации:

1. **Куда тапать, чтобы открыть бабл?** В требованиях (`docs/pinchmap-requirements.md:84`) — «тап по такой ноде», в плане фазы (`docs/specs/pinchmap-discovery.md:105`) — «тап по ней» (по иконке). Варианты: а) только по иконке, тап по ноде выделяет как обычно; б) тап по уже выделенной ноде со ссылкой открывает бабл; в) любой тап по ноде со ссылкой.
2. **Где стоит иконка ссылки?** а) внутри ноды, в конце текста (увеличивает ширину); б) бейдж в углу ноды поверх рамки (верхний правый угол, не мешает «+»); в) слева от текста.
3. **Иконка: одна для всех ссылок (`link`) или разные** для вики-ссылки (`link`) и внешней (`external-link`)?
4. **Несколько ссылок в ноде:** бабл со списком всех ссылок или только первая?
5. **Максимальная высота миниатюры:** например 120 / 160 / 200 px (ширина ограничена 300 px ноды).
6. **Заголовки (`# …`) внутри ноды:** приводить к размеру текста ноды (вес semibold) или оставить размеры темы?
7. **Точка вставки картинки:** пункт в контекстном меню ноды, кнопка в панели над клавиатурой при редактировании, или оба?
8. **Фон бабла:** `--background-primary` (как поле ввода) или `--background-secondary` (как панель «Готово»)?

## 6. Чек-лист для фазы 2

- [ ] Все цвета — переменные Obsidian; проверено в светлой и тёмной теме по умолчанию.
- [ ] Новые классы с префиксом `pinchmap-`, состояния через `is-*`.
- [ ] Зоны касания иконки ссылки и кнопок бабла ≥ 44×44 px на экране при любом зуме.
- [ ] Ссылки, теги и картинки внутри ноды не перехватывают тап; долгое нажатие на картинку не вызывает меню iOS.
- [ ] У рендера нет внешних отступов абзацев; длинные URL и код не выходят за 300 px; горизонтального скролла внутри ноды нет.
- [ ] Иконки — SVG Lucide через `setIcon`, у интерактивных — `aria-label` из i18n.
- [ ] Видимый фокус у кнопок бабла; Esc закрывает бабл.
- [ ] Тип ссылки (вики/внешняя) различается не только цветом.
- [ ] Анимации (если будут) ≤ 300 мс и отключаются при `prefers-reduced-motion`.
- [ ] Нода перемеряется после асинхронного рендера и загрузки картинки.


## 7. Решения разработчика по открытым вопросам (раздел 5)

1. Бабл открывается **тапом по ноде** со ссылкой (как в требованиях): тап выделяет ноду и показывает бабл; двойной тап — редактирование.
2. Иконка ссылки — **бейдж в углу ноды**, размер ноды не меняет.
3. **Одна иконка** для всех типов ссылок; тип различается уже в бабле.
4. Если ссылок несколько — бабл показывает **только первую**.
5. Максимальная высота миниатюры — **160px**.
6. Заголовки внутри ноды — **размер текста ноды, жирные**.
7. «Вставить картинку» — **в обоих местах**: контекстное меню ноды и панель над клавиатурой при редактировании.
8. Фон бабла — **как у панели «Готово»**.
