# Pinchmap — правила работы

## Всегда работаем по фреймворку Bee

Любую задачу в этом проекте — фичу, доработку UX, багфикс, рефакторинг — ведём через Bee, а не правим код напрямую.

- Точка входа: `/bee:start` (триаж и выбор цепочки) или `/bee:sdd` (spec-driven development).
- Порядок: триаж → контекст → (discovery) → спек → архитектура → срезы по одному (код → тесты → проверка) → ревью.
- Код пишут, тестируют и проверяют специализированные агенты Bee (slice-coder, slice-tester, sdd-verifier, reviewer). Один срез за раз.
- Спеки и ревью лежат в `docs/specs/`, источник правды по поведению — `docs/pinchmap-requirements.md`.
- Границы модулей — `.claude/BOUNDARIES.md`; они же проверяются ESLint (`npm run lint`).
- Тривиальные правки (опечатка, конфиг, документация) можно делать сразу, без спека.

## Прочее

- Документы проекта пишем по-русски, код и комментарии — по-английски.
- Перед коммитом: `npm run lint`, `npm test`, `npm run build`.
- Каждая пользовательская доработка повышает версию в `package.json`, `manifest.json` и `versions.json`.
