### Should-fix (исправить в 0.1.13)

**S1. После удаления всех нод картой становится следующий список заметки, и в чужой текст дописываются `^id`.**
`src/format/listRegion.ts:59-62` (`findListStart`) вместе с `src/format/serializeMapFile.ts:7-13`.
Сценарий:
1. Карта `- Project` и под ней раздел `## Notes` со списком `- buy milk`, `- call Bob`.
2. Пользователь удаляет единственный root (по спеку это разрешено), автосохранение записывает файл без списка карты.
3. При следующем открытии `buy milk` и `call Bob` показаны как root карты.
4. Любая правка (например, «Добавить ноду») дописывает `^lu30rk`, `^hzxrd9` к заметкам пользователя и вставляет новый root внутрь его списка.

Воспроизведено скриптом. Это нарушает обещание «текст вне карты не меняется».
Варианты исправления: не давать удалить последний root (оставлять пустой root), или при пустой карте писать пустой пункт-заглушку `- ` на месте списка. Нужно решение разработчика.

**S2. Список внутри блока кода считается картой; при конвертации и правках `^id` попадают в код.**
`src/format/listRegion.ts:59-62` и `69-79`: `findListStart` и `findListEnd` не учитывают блоки кода ```` ``` ```` / `~~~` (и `%%`-комментарии, `$$`).
Сценарий: «Превратить эту заметку в карту» на техзаметке вида `# Setup` → блок кода с `- npm install` → `- real item`. Результат: `- npm install ^2z0a5s` внутри блока кода, а настоящий список уходит в «текст вне карты». То же для отступленного блока кода внутри пункта: строка `  - code` становится нодой и получает `^id` при первой правке.
Исправление: при поиске начала и конца списка пропускать строки внутри блоков кода и `%%`-блоков. Добавить фикстуры с блоками кода в `roundTrip.test.ts` и `convertNoteToMap.test.ts`.

**S3. Ошибка автосохранения не видна пользователю.**
`src/obsidian/mapView.ts:28-32`: ошибка уходит только в `console.error`.
Сценарий: на iPad iCloud-хранилище на мгновение недоступно, или файл переименовали либо удалили с другого устройства. `vault.modify` выбрасывает ошибку, пользователь продолжает работать, правки нигде не сохранены. На iPhone консоль недоступна.
Исправление: показывать `Notice` (как `reportFailure`), например «Карта не сохранена: …», и не сбрасывать флаг «есть несохранённое», чтобы следующая правка повторила запись.

**S4. Внешнее изменение, совпавшее с одной из 5 последних собственных записей, молча игнорируется.**
`src/obsidian/externalChangeGate.ts:263-284` (`dropKnownTextsOlderThan`).
Сценарий:
1. Пользователь делает правки T1 → T2 → T3, и они сохраняются.
2. Через «Восстановление файлов» или git он откатывает файл к T2.
3. T2 есть в списке известных текстов, поэтому вид продолжает показывать T3, а на диске лежит T2.
4. Следующая правка записывает T4 поверх отката. Откат пропадает без уведомления.

Исправление: считать «эхом» только самую последнюю собственную запись (или сравнивать с `getViewData()`), а не любую из последних пяти. Добавить тест в `externalChangeGate.test.ts`.

**S5. Несохранённый ввод текста при уходе приложения в фон (iOS).**
Ввод фиксируется по Done, Esc, Ctrl+Enter или `blur` (`src/editor/textEditSession.ts:54`). Подписки на `visibilitychange` / `pagehide` нет нигде в `src/`.
Сценарий: на iPhone пользователь набирает длинный текст ноды и смахивает в другое приложение. Если WebKit не пошлёт `blur` полю ввода, а iOS выгрузит Obsidian, весь текст пропадёт. Встроенный редактор Markdown в такой ситуации сохранил бы текст через 2 с.
Исправление: при `visibilitychange` → `hidden` вызывать `commitPendingEdit()` и `autosave.flush()`. Добавить этот пункт в ручной чек-лист.

**S6. Риски release workflow** (`.github/workflows/release.yml`):
- **стр. 9-11:** релиз собирается при пуше в **любую** ветку `claude/**`. Будущая экспериментальная ветка с той же версией в `manifest.json` перезапишет (`--clobber`, стр. 45) файлы релиза, которым пользуются тестеры. Тег при этом продолжит указывать на старый коммит (`--target` есть только при создании, стр. 48). Это уже произошло: файлы 0.1.12 перезалиты пушем merge в `main`, а тег смотрит на `eaa3040`. Если в ветке с меньшей версией сделать пуш позже, её релиз станет «latest» на GitHub.
  Рекомендация: релизить только из `main` (или одной явно названной beta-ветки). Для веток собирать prerelease с суффиксом, например `0.1.13-beta.<sha>`. Если тег уже есть и указывает на другой коммит, завершать сборку ошибкой, а не перезаливать файлы.
- **стр. 36-37:** нет `npm run lint`, поэтому границы модулей в CI не проверяются. Добавить шаг (≈2 с).
- **стр. 32:** `node-version: 20`, а `vitest@5` требует Node `^22.12 || ^24 || >=26` (`engines`). Сейчас тесты проходят случайно. Node 20 вышел из поддержки в апреле 2026. Поставить 22 или 24.
- Нет проверки, что версии в `package.json`, `manifest.json` и `versions.json` совпадают (сейчас совпадают: 0.1.12).

### Nice-to-have

- **N1.** `src/format/listRegion.ts:4`: `LIST_LINE` принимает тематический разрыв `* * *` / `- - -` за пункт. Если такой разрыв стоит сразу после карты через пустую строку, он становится root, а при правке получает `^id` и перестаёт быть линией. Пример: `- a\n\n* * *\n\nOutro`.
- **N2.** `src/format/serializeMapFile.ts:61`: `renderNewItemLines` вызывается без конца строки файла, поэтому в CRLF-файле новые пункты пишутся с `\n` и концы строк становятся смешанными. Obsidian это переживает, но в git появляется шум. Передавать `detectLineEnding(source)`.
- **N3.** `src/format/parseMapFile.ts:80-86` и `src/format/jsonBlock.ts:82-84`: если в хвосте нет JSON-блока, служебным считается любой `%%`/```` ```json ````-блок **до** списка, даже без `nodes`. При конвертации пользовательский блок `{"foo":1}` переписывается в `{"version":1,"nodes":{},"foo":1}`. Принимать блок в начале файла, только если в нём есть `nodes` или `version`.
- **N4.** `hasMindmapFlag` (`src/format/frontmatter.ts:6`, регулярное выражение) и `isMapNote` (`src/obsidian/mapNotes.ts:9`, `metadataCache === true`) по-разному понимают флаг. При `mindmap: True` или `mindmap: true # map` команда «Открыть как карту» доступна, а автооткрытие файла как карты не срабатывает. Одно правило для обоих мест.
- **N5.** Пустые строки после пункта переезжают вместе с ним при удалении или переносе ветки, поэтому на стыке списка и текста за ним постепенно копятся пустые строки. Текст не теряется.
- **N6.** `src/obsidian/mapView.ts:55-69`: подписи «Добавить дочернюю / соседнюю / Свернуть / Развернуть» передаются дважды (`nodeMenuLabels` и `labels`). Свести к одному объекту.
- **N7.** `src/editor/mapEditor.ts` (512 строк, 39 методов) — composition root, на нём держится всё. Пока читается. Перед фазой 2 стоит вынести подключение ввода (`attachInput` / `handleIntent`).

## Известные замечания из проверки срезов

Ни одно не блокирует выпуск: данные они не портят, или есть обходной путь.

- **Не блокируют, оставить в бэклоге:** Ctrl+/ на русской раскладке (есть пункт в меню), ребёнок свёрнутого root всегда справа, двойной тап по индикатору, ghost-tap в подменю цвета на iPad, меню во всплывающем окне, колесо во время перетаскивания, долгое нажатие на ноде группы, Ctrl+C без выделения, устаревшие x/y (файл они не портят).
- **Стоит сделать вместе с S-пунктами:** `^word` в конце вставленных строк считается ID и вырезается из текста вставки (`src/format/pastedBranches.ts`). Пользователь теряет кусок вставленного текста. Это небольшая потеря текста, поэтому её место в should-fix.
- **Пренебрежимо малы:** переполнение стека на ~2000 уровнях вложенности (файл просто не открывается, порчи нет) и коллизия новых ID с осиротевшими записями JSON (вероятность ~1/36⁶, состояние сирот при разборе всё равно не используется).
