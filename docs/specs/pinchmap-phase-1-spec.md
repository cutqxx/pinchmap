# Spec: Pinchmap — Фаза 1 (MVP): редактор карты для тестеров

> Статус: **черновик**. В нём есть пункты с пометкой «ОТКРЫТЫЙ ВОПРОС ОВ-N»: они ждут решения разработчика (список вопросов в конце документа). Пока они открыты, спек не утверждён.
>
> Источники: [требования](../pinchmap-requirements.md) (источник правды по поведению), [discovery](pinchmap-discovery.md) (фаза 1, срезы 1а–1г), [границы модулей](../../.claude/BOUNDARIES.md).

## Обзор

MVP Pinchmap — редактор mind map внутри Obsidian, которым одинаково удобно пользоваться пальцами на iPhone и iPad и мышью с клавиатурой на ПК. Карта хранится в обычном `.md`-файле: вложенный список плюс скрытый JSON-блок. Файл переживает любое число циклов «открыть — изменить — сохранить» без потерь. Ориентир по объёму — карты примерно до 200 нод. Оформление берётся из темы Obsidian, текст нод показывается как обычный текст с переносами строк. Первая выдача тестерам (BRAT / ручная установка) — после среза 1г (Slice 17).

## Как читать критерии

У каждого критерия в конце стоит пометка о том, как его проверять:

- `[unit: <модуль>/]` — проверяется unit-тестом модуля без фреймворка (`model/`, `format/`, `commands/`, `layout/`, `viewport/`, `input/`, `editor/`). Obsidian для такой проверки не нужен.
- `[вручную: iPad]`, `[вручную: iPhone]`, `[вручную: ПК]` — ручная проверка в Obsidian на указанном устройстве. `[вручную: iPad+ПК]` — на обоих.
- Если стоят обе пометки, логику проверяет unit-тест, а связку с устройством — ручная проверка.

Срезы идут по порядку discovery (1а → 1г). Каждый следующий срез опирается на предыдущие.

## Срез 1а: открыть, показать, изменить, сохранить

### Slice 1: Walking skeleton — открыть карту, поправить текст ноды, сохранить

Самый тонкий сквозной путь: файл открывается как карта, текст ноды правится двойным тапом или двойным кликом и сохраняется в файл. Раскладка здесь простейшая: дети стоят справа от родителя, в столбик. Перемещения по канвасу, зума и создания нод в этом срезе нет.

- [ ] Файл с `mindmap: true` во frontmatter открывается в виде карты, а не в редакторе Markdown `[вручную: iPad+ПК]`
- [ ] Файл без `mindmap: true` открывается обычным редактором Markdown `[вручную: ПК]`
- [ ] Команда «Открыть как Markdown» в палитре команд открывает текущую карту в редакторе Markdown `[вручную: iPad+ПК]`
- [ ] Каждый пункт списка показан на карте нодой со своим текстом, без `^id` `[вручную: iPad+ПК]`
- [ ] Ребёнок соединён с родителем линией и стоит справа от него; дети одного родителя идут в столбик в порядке списка `[unit: layout/]` `[вручную: ПК]`
- [ ] Двойной тап или двойной клик по ноде открывает ввод её текста `[вручную: iPad+ПК]`
- [ ] Тап или клик вне редактируемой ноды завершает ввод, и нода показывает новый текст `[вручную: iPad+ПК]`
- [ ] Esc завершает ввод и сохраняет введённый текст (не отменяет его) `[вручную: ПК]`
- [ ] Примерно через 1 секунду после последнего изменения файл сохраняется; новый текст виден, если открыть файл как Markdown `[вручную: iPad+ПК]`
- [ ] Несколько правок с интервалом меньше 1 секунды приводят к одной записи файла `[unit: с поддельным таймером]`
- [ ] Разбор файла даёт дерево: пункт верхнего уровня — root, вложенный пункт — ребёнок ближайшего пункта уровнем выше; `^id` в конце пункта становится ID ноды и не входит в её текст `[unit: format/]`
- [ ] Чтение и сохранение без изменений возвращает файл байт в байт: frontmatter, список и JSON-блок `[unit: format/]`
- [ ] После правки текста одной ноды в файле меняется только строка этого пункта `[unit: format/]`
- ОТКРЫТЫЙ ВОПРОС ОВ-1: какой список в файле считается картой, если в файле несколько списков или текст перед списком.

### Slice 2: Формат без потерь — многострочный текст, отступы, текст вне списка

- [ ] Пункт с продолжением строк (строки с отступом под пунктом) читается как одна нода с многострочным текстом `[unit: format/]`
- [ ] Многострочный текст ноды записывается как пункт с продолжением строк и после повторного чтения совпадает с исходным `[unit: format/]`
- [ ] Отступы табами, двумя пробелами и четырьмя пробелами разбираются в одинаковое дерево `[unit: format/]`
- [ ] Строки существующих пунктов сохраняют свой исходный отступ после любой правки в другом месте карты `[unit: format/]`
- [ ] Новые пункты записываются с отступом по правилу ОВ-3 `[unit: format/]` — ОТКРЫТЫЙ ВОПРОС ОВ-3
- [ ] Текст вне списка и вне JSON-блока (абзацы, заголовки, текст после JSON-блока) остаётся байт в байт после любой правки карты `[unit: format/]`
- [ ] Текст вне списка на карте не показывается `[вручную: ПК]`
- [ ] Дополнительные поля frontmatter (кроме `mindmap`) сохраняются без изменений `[unit: format/]`
- [ ] Текст ноды с Markdown-разметкой (`**жирный**`, `[[ссылка]]`) показывается как есть, обычным текстом с переносами строк `[вручную: ПК]`
- [ ] Файл с пустым списком открывается как пустая карта без ошибки `[unit: format/]` `[вручную: ПК]`

### Slice 3: ID нод, служебный JSON и изменения файла извне

- [ ] При сохранении изменений пункту без `^id` молча дописывается новый ID, уникальный в пределах файла `[unit: format/]` — формат ID: ОТКРЫТЫЙ ВОПРОС ОВ-2
- [ ] Строки пунктов, у которых ID уже был, при простановке ID не меняются `[unit: format/]`
- [ ] Открытие и просмотр карты без правок файл не меняет, даже если у пунктов нет ID `[unit: format/]` `[вручную: ПК]`
- [ ] JSON-блок записывается в `%% ... %%` в конце файла, по одной ноде на строку `[unit: format/]`
- [ ] В JSON попадают только ноды с собственным состоянием (ручная позиция, свёрнутость, цвет); ноды без него в JSON не пишутся `[unit: format/]`
- [ ] Записи JSON для ID, которых больше нет в списке, при сохранении удаляются `[unit: format/]`
- [ ] Файл с повреждённым JSON-блоком обрабатывается по правилу ОВ-4 `[unit: format/]` `[вручную: ПК]` — ОТКРЫТЫЙ ВОПРОС ОВ-4
- [ ] Файл, в котором один `^id` стоит у нескольких пунктов, обрабатывается по правилу ОВ-5 `[unit: format/]` — ОТКРЫТЫЙ ВОПРОС ОВ-5
- [ ] Если файл изменился извне (синхронизация или правка в другом окне), открытая карта перечитывает его и показывает новое содержимое `[вручную: iPad+ПК]`
- [ ] Если файл изменился извне, а в карте есть несохранённые правки, действует правило ОВ-6 `[вручную: ПК]` — ОТКРЫТЫЙ ВОПРОС ОВ-6

### Slice 4: Автораскладка и несколько root

Размеры нод `layout/` получает извне; в unit-тестах их задают явно.

- [ ] Первая ветка первого уровня встаёт справа от root `[unit: layout/]`
- [ ] Очередная ветка первого уровня встаёт слева, если правая сторона root выше левой, и справа во всех остальных случаях (при равной высоте — справа) `[unit: layout/]` — устойчивость стороны: ОТКРЫТЫЙ ВОПРОС ОВ-7
- [ ] Ветка на левой стороне раскладывается зеркально: её дети стоят слева от родителя `[unit: layout/]`
- [ ] Габариты соседних веток не пересекаются при любых размерах нод `[unit: layout/]`
- [ ] Ширина ноды и выравнивание родителя относительно детей — по правилу ОВ-9 `[unit: layout/]` — ОТКРЫТЫЙ ВОПРОС ОВ-9
- [ ] Каждый пункт верхнего уровня показан отдельным деревом со своим root `[вручную: ПК]`
- [ ] Деревья разных root не перекрываются; root без сохранённой позиции ставится по правилу ОВ-8 `[unit: layout/]` — ОТКРЫТЫЙ ВОПРОС ОВ-8
- [ ] Root отличается от остальных нод стилем по умолчанию (например, крупнее шрифт или толще рамка), цвета берутся из CSS-переменных темы Obsidian `[вручную: ПК]`
- [ ] Карта выглядит читаемо в светлой и тёмной теме Obsidian: текст нод контрастен фону (не ниже 4,5:1) `[вручную: ПК]`
- [ ] Проверка гипотезы H1: карта примерно на 200 нод открывается на iPad, а перемещение и зум идут без рывков, заметных на глаз; результат записан в заметки к срезу `[вручную: iPad]`

### Slice 5: Перемещение по канвасу и зум

- [ ] Ведение одним пальцем по пустому месту двигает канвас `[unit: input/]` `[вручную: iPad]`
- [ ] Ведение одним пальцем по канвасу не открывает боковые панели Obsidian и не вызывает навигацию «назад» (гипотеза H2) `[вручную: iPad+iPhone]`
- [ ] Щипок двумя пальцами меняет зум; точка карты между пальцами остаётся под пальцами `[unit: viewport/]` `[вручную: iPad]`
- [ ] Прокрутка колесом или двумя пальцами на тачпаде двигает канвас; Shift+колесо — по горизонтали `[вручную: ПК]`
- [ ] Ctrl/Cmd+колесо и щипок на тачпаде меняют зум; точка карты под курсором остаётся на месте `[unit: viewport/]` `[вручную: ПК]`
- [ ] Перетаскивание с зажатым пробелом или средней кнопкой мыши двигает канвас `[вручную: ПК]`
- [ ] Перетаскивание левой кнопкой мыши по пустому месту канвас не двигает (это жест рамки, Slice 17) `[unit: input/]`
- [ ] Зум не выходит за пределы из ОВ-17 `[unit: viewport/]` — ОТКРЫТЫЙ ВОПРОС ОВ-17
- [ ] Перевод координат «экран → карта → экран» возвращает исходную точку при любом зуме и сдвиге `[unit: viewport/]`
- [ ] Apple Pencil двигает канвас и зумит так же, как палец `[вручную: iPad]`

### Slice 6: Выделение, добавление и удаление нод

- [ ] Тап или клик по ноде выделяет её, выделение видно на карте `[вручную: iPad+ПК]`
- [ ] Тап или клик по пустому месту снимает выделение `[unit: editor/]` `[вручную: iPad+ПК]`
- [ ] У выделенной ноды видны две кнопки «+»: справа — добавить дочернюю, снизу — добавить соседнюю; зона нажатия каждой кнопки не меньше 44×44 px `[вручную: iPad+ПК]`
- [ ] «+» справа и Tab добавляют ребёнка последним среди детей выделенной ноды `[unit: commands/]`
- [ ] «+» снизу и Enter добавляют соседнюю ноду сразу после выделенной `[unit: commands/]`
- [ ] Enter и «+» снизу у выделенного root работают по правилу ОВ-11 `[unit: commands/]` — ОТКРЫТЫЙ ВОПРОС ОВ-11
- [ ] Новая нода сразу выделена и открыта на ввод текста `[unit: editor/]` `[вручную: iPad+ПК]`
- [ ] Новая нода, ввод в которой завершён с пустым текстом, обрабатывается по правилу ОВ-10 `[unit: editor/]` — ОТКРЫТЫЙ ВОПРОС ОВ-10
- [ ] Delete или Backspace удаляет выделенную ноду вместе со всеми потомками `[unit: commands/]` `[вручную: ПК]`
- [ ] После удаления ветки выделение переходит по правилу ОВ-12 `[unit: editor/]` — ОТКРЫТЫЙ ВОПРОС ОВ-12
- [ ] Delete и Backspace в режиме ввода текста правят текст и ноду не удаляют `[вручную: ПК]`
- [ ] Горячие клавиши карты срабатывают, только когда активен вид карты; в других вкладках Obsidian они не перехватываются `[вручную: ПК]`

### Slice 7: Полноценный ввод текста на всех устройствах

- [ ] F2 открывает ввод текста выделенной ноды `[unit: input/]` `[вручную: ПК]`
- [ ] Enter в режиме ввода переносит строку и не создаёт новую ноду `[вручную: iPad+ПК]`
- [ ] Ctrl/Cmd+Enter завершает ввод и сохраняет текст `[вручную: ПК]`
- [ ] На iPhone и iPad над экранной клавиатурой есть кнопка «Готово», которая завершает ввод `[вручную: iPad+iPhone]`
- [ ] Когда открывается экранная клавиатура, канвас сдвигается так, что редактируемая нода целиком видна над клавиатурой `[unit: viewport/]` `[вручную: iPad+iPhone, обе ориентации]`
- [ ] Если нода уже видна над клавиатурой, канвас не сдвигается `[unit: viewport/]`
- [ ] Многострочный текст показывается в ноде с теми же переносами строк, что и при вводе `[вручную: iPad+ПК]`
- [ ] Esc вне режима ввода снимает выделение `[unit: editor/]`
- [ ] Ввод с аппаратной клавиатуры на iPad работает так же, как на ПК (Tab, Enter, F2, Esc, Ctrl/Cmd+Enter) `[вручную: iPad + клавиатура]`

## Срез 1б: создание карт, undo/redo, навигация

### Slice 8: Новая карта и превращение заметки в карту

- [ ] Команда «Новая карта» в палитре команд создаёт файл карты в папке для новых заметок из настроек Obsidian и открывает его как карту `[вручную: iPad+ПК]`
- [ ] Кнопка «Новая карта» на ленте (ribbon) делает то же, что команда `[вручную: ПК]`
- [ ] Имя нового файла и его начальное содержимое — по правилу ОВ-13; имя не совпадает с уже существующим файлом `[unit: format/]` `[вручную: ПК]` — ОТКРЫТЫЙ ВОПРОС ОВ-13
- [ ] Команда «Превратить эту заметку в карту» доступна только в обычной заметке без `mindmap: true` `[вручную: ПК]`
- [ ] Превращение добавляет `mindmap: true` во frontmatter и не трогает остальные его поля `[unit: format/]`
- [ ] Превращение создаёт frontmatter, если его не было `[unit: format/]`
- [ ] Превращение дописывает `^id` каждому пункту списка без ID; остальной текст заметки не меняется `[unit: format/]`
- [ ] После превращения заметка открывается как карта `[вручную: iPad+ПК]`
- [ ] Заметка без списка превращается по правилу ОВ-14 `[unit: format/]` — ОТКРЫТЫЙ ВОПРОС ОВ-14
- [ ] Из режима Markdown можно вернуться к виду карты по правилу ОВ-15 `[вручную: ПК]` — ОТКРЫТЫЙ ВОПРОС ОВ-15

### Slice 9: Добавление root и меню на пустом месте

- [ ] Долгое нажатие на пустом месте открывает меню с пунктом «Добавить ноду» `[unit: input/]` `[вручную: iPad]`
- [ ] Правая кнопка мыши на пустом месте открывает то же меню `[вручную: ПК]`
- [ ] «Добавить ноду» создаёт новый root и сразу открывает его на ввод текста `[unit: commands/]` `[вручную: iPad+ПК]`
- [ ] Двойной клик по пустому месту создаёт новый root и открывает его на ввод `[вручную: ПК]`
- [ ] На пустом канвасе «Добавить ноду» создаёт первый root `[unit: commands/]`
- [ ] Новый root появляется в месте по правилу ОВ-8 `[unit: layout/]` — ОТКРЫТЫЙ ВОПРОС ОВ-8
- [ ] Новый root записывается в файл последним пунктом верхнего уровня `[unit: format/]`
- [ ] Нажатие короче заданной длительности долгого нажатия меню не открывает `[unit: input/]`
- [ ] Если палец сдвинулся дальше порога перетаскивания до истечения долгого нажатия, меню не открывается `[unit: input/]`
- [ ] В настройках плагина задаётся длительность долгого нажатия, по умолчанию 0,5 с; допустимый диапазон — по ОВ-17 `[unit: input/]` `[вручную: iPad]` — ОТКРЫТЫЙ ВОПРОС ОВ-17

### Slice 10: Undo / redo

- [ ] В тулбаре карты на всех устройствах есть кнопки «Отменить» и «Повторить»; зона нажатия не меньше 44×44 px `[вручную: iPad+ПК]`
- [ ] Кнопка «Отменить» неактивна, когда отменять нечего; «Повторить» — когда нечего повторять `[unit: commands/]` `[вручную: ПК]`
- [ ] Ctrl/Cmd+Z отменяет последнее действие, Ctrl/Cmd+Shift+Z повторяет отменённое `[вручную: ПК]`
- [ ] Тап двумя пальцами отменяет, тап тремя пальцами повторяет `[unit: input/]` `[вручную: iPad]`
- [ ] Щипок и движение двумя пальцами undo не вызывают `[unit: input/]`
- [ ] Тап тремя пальцами не перехватывается системным меню iOS «Отменить/Повторить» (гипотеза H2) `[вручную: iPad+iPhone]`
- [ ] Отмена удаления возвращает всю ветку с прежними ID, местом в списке и состоянием из JSON `[unit: commands/]`
- [ ] Одна сессия ввода текста отменяется одним шагом: возвращается текст, который был до начала ввода `[unit: commands/]`
- [ ] Новое действие после отмены очищает историю повтора `[unit: commands/]`
- [ ] Молчаливая простановка ID в историю undo не попадает `[unit: commands/]` `[unit: format/]`
- [ ] Результат undo и redo сохраняется в файл автосохранением `[вручную: ПК]`

### Slice 11: Навигация стрелками и зум с клавиатуры

- [ ] Стрелки ↑ и ↓ переходят к предыдущей и следующей соседней ноде `[unit: editor/]`
- [ ] Стрелки ← и → переходят к родителю или ребёнку по правилу ОВ-16 `[unit: editor/]` — ОТКРЫТЫЙ ВОПРОС ОВ-16
- [ ] Стрелка без выделенной ноды работает по правилу ОВ-16 `[unit: editor/]` — ОТКРЫТЫЙ ВОПРОС ОВ-16
- [ ] Стрелка у границы (нет соседа, родителя или ребёнка в этом направлении) оставляет выделение на месте `[unit: editor/]`
- [ ] Если выбранная стрелками нода за пределами экрана, канвас сдвигается так, чтобы она стала видна `[unit: viewport/]`
- [ ] Ctrl/Cmd+0 вписывает все ноды карты в экран `[unit: viewport/]` `[вручную: ПК]`

## Формы данных (ориентир)

Файл карты:

````markdown
---
mindmap: true
---
- Главная тема ^a1b2
    - Подтема ^c3d4
      продолжение многострочного текста
    - Ещё подтема ^e5f6
- Вторая главная тема ^g7h8

%%
```json
{
"version": 1,
"nodes": {
"a1b2": {"x": 0, "y": 0, "pinned": true, "collapsed": false, "color": null},
"c3d4": {"x": 40, "y": -20, "pinned": true, "collapsed": true, "color": "red"}
},
"style": {}
}
```
%%
````

Точный вид координат (относительно родителя или абсолютные), значения цвета и формат ID зависят от ОВ-2, ОВ-18 и ОВ-20. Поле `style` в MVP пишется пустым и сохраняется как есть.

Модель (ориентир для `model/`):

```
MindMap { roots: Node[] }
Node    { id: NodeId, text: string, children: Node[],
          pinnedPosition?: {x, y}, collapsed: boolean, color?: ColorName }
```

## Вне рамок (Out of scope)

- Рендер Markdown в нодах (жирный, курсив, код, ссылки, теги), иконка и бабл ссылки, картинки и вложения — **фаза 2**.
- Отрисовка только видимой области, частичный пересчёт раскладки, цели «1000 нод быстрее 1 с» и «60 fps», повторяемый замер — **фаза 3**. Если гипотеза H1 (200 нод) не подтвердится, часть фазы 3 переезжает в MVP отдельным решением.
- Встраивание `![[карта]]` с превью — **фаза 4**.
- Палитры веток, формы нод, стили связей, толщина линий, отступы, размер шрифта, пресеты, настройки оформления для отдельной карты — **фаза 5**. В MVP пользователь меняет только цвет ноды.
- Поиск по карте и Ctrl/Cmd+F — **фаза 6**.
- Экспорт в PNG, SVG, PDF и чистый Markdown — **фаза 7**.
- Публикация в каталоге плагинов Obsidian: MVP распространяется через BRAT или ручную установку.
- Групповые операции, кроме перемещения: удаление, цвет, копирование и смена родителя для нескольких выделенных нод.
- Изменение порядка соседних нод перетаскиванием.
- Связи между разными ветками, альтернативные форматы хранения, сжатие JSON, собственная синхронизация, особые возможности Apple Pencil — вне проекта целиком.

## Технический контекст

- Проект с нуля (greenfield): пока нет `package.json`, сборки и тестового окружения. Плагин для Obsidian на TypeScript.
- Границы модулей — [.claude/BOUNDARIES.md](../../.claude/BOUNDARIES.md). Пакет `obsidian` импортирует только `obsidian/`. Модули `model/`, `format/`, `commands/`, `layout/`, `viewport/`, `input/`, `editor/` не зависят от фреймворка, и на них приходится основная часть пометок `[unit: …]`.
- Тесты пишутся после кода. Поэтому критерии с пометкой `[unit: …]` сформулированы через входы и выходы чистых функций и модулей: текст файла ↔ дерево, дерево + размеры нод → позиции, команда → новое состояние и обратная команда, последовательность событий указателя → намерение.
- Главный риск — порча файлов пользователя. Для `format/` нужен набор реальных файлов «прочитал — сохранил — сравнил»: табы и пробелы, многострочные пункты, текст вне списка, ручные правки, повреждённый JSON, дублирующиеся ID.
- Оформление берётся только из CSS-переменных темы Obsidian. Отдельного `DESIGN.md` нет, работа над внешним видом — фаза 5.
- Уровень риска: MODERATE.
- Открытый вопрос discovery, не блокирующий спек: на каких моделях iPad и iPhone проверять. Желательно решить к ручной проверке Slice 5 (жесты, H2).
