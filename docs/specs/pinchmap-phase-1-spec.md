# Spec: Pinchmap — Фаза 1 (MVP): редактор карты для тестеров

> Статус: открытые вопросы ОВ-1 – ОВ-23 решены разработчиком 2026-10-29 (выбран вариант (а) во всех вопросах). Решения перечислены в разделе «Решения» в конце документа.
>
> Источники: [требования](../pinchmap-requirements.md) (источник правды по поведению), [discovery](pinchmap-discovery.md) (фаза 1, срезы 1а–1г), [границы модулей](../../.claude/BOUNDARIES.md).

## Обзор

MVP Pinchmap — редактор mind map внутри Obsidian, которым одинаково удобно пользоваться пальцами на iPhone и iPad и мышью с клавиатурой на ПК. Карта хранится в обычном `.md`-файле: вложенный список плюс скрытый JSON-блок. Файл переживает любое число циклов «открыть — изменить — сохранить» без потерь. Ориентир по объёму — карты примерно до 200 нод. Оформление берётся из темы Obsidian, текст нод показывается как обычный текст с переносами строк. Первая выдача тестерам (BRAT / ручная установка) — после среза 1г (Slice 17).

## Как читать критерии

У каждого критерия в конце стоит пометка о том, как его проверять:

- `[unit: <модуль>/]` — проверяется unit-тестом модуля без фреймворка (`model/`, `format/`, `commands/`, `layout/`, `viewport/`, `input/`, `editor/`). Obsidian для такой проверки не нужен.
- `[вручную: iPad]`, `[вручную: iPhone]`, `[вручную: ПК]` — ручная проверка в Obsidian на указанном устройстве. `[вручную: iPad+ПК]` — на обоих.
- Если стоят обе пометки, логику проверяет unit-тест, а связку с устройством — ручная проверка.

Срезы идут по порядку discovery (1а → 1г). Каждый следующий срез опирается на предыдущие.

## Срез 1а: открыть, показать, изменить, сохранить

### Slice 1: Walking skeleton — открыть карту, поправить текст ноды, сохранить

Самый тонкий сквозной путь: файл открывается как карта, текст ноды правится двойным тапом или двойным кликом и сохраняется в файл. Раскладка здесь простейшая: дети стоят справа от родителя, в столбик. Перемещения по канвасу, зума и создания нод в этом срезе нет.

- [ ] Файл с `mindmap: true` во frontmatter открывается в виде карты, а не в редакторе Markdown `[вручную: iPad+ПК]`
- [ ] Файл без `mindmap: true` открывается обычным редактором Markdown `[вручную: ПК]`
- [ ] Команда «Открыть как Markdown» в палитре команд открывает текущую карту в редакторе Markdown `[вручную: iPad+ПК]`
- [x] Картой считается первый непрерывный список после frontmatter `[unit: format/]`
- [ ] Каждый пункт этого списка показан на карте нодой со своим текстом, без `^id` `[вручную: iPad+ПК]`
- [ ] Ребёнок соединён с родителем линией и стоит справа от него; дети одного родителя идут в столбик в порядке списка `[unit: layout/]` `[вручную: ПК]`
- [ ] Двойной тап или двойной клик по ноде открывает ввод её текста `[вручную: iPad+ПК]`
- [ ] Тап или клик вне редактируемой ноды завершает ввод, и нода показывает новый текст `[вручную: iPad+ПК]`
- [ ] Esc завершает ввод и сохраняет введённый текст (не отменяет его) `[вручную: ПК]`
- [ ] Примерно через 1 секунду после последнего изменения файл сохраняется; новый текст виден, если открыть файл как Markdown `[вручную: iPad+ПК]`
- [x] Несколько правок с интервалом меньше 1 секунды приводят к одной записи файла `[unit: с поддельным таймером]`
- [x] Разбор файла даёт дерево: пункт верхнего уровня — root, вложенный пункт — ребёнок ближайшего пункта уровнем выше; `^id` в конце пункта становится ID ноды и не входит в её текст `[unit: format/]`
- [x] Чтение и сохранение без изменений возвращает файл байт в байт: frontmatter, список и JSON-блок `[unit: format/]`
- [x] После правки текста одной ноды в файле меняется только строка этого пункта `[unit: format/]`

### Slice 2: Формат без потерь — многострочный текст, отступы, текст вне списка

- [x] Пункт с продолжением строк (строки с отступом под пунктом) читается как одна нода с многострочным текстом `[unit: format/]`
- [x] Многострочный текст ноды записывается как пункт с продолжением строк и после повторного чтения совпадает с исходным `[unit: format/]`
- [x] Список карты заканчивается на первой непустой строке, которая не является ни пунктом списка, ни продолжением пункта с отступом `[unit: format/]`
- [x] Текст между frontmatter и первым списком, а также все последующие списки считаются текстом вне карты `[unit: format/]`
- [x] Отступы табами, двумя пробелами и четырьмя пробелами разбираются в одинаковое дерево `[unit: format/]`
- [x] Строки существующих пунктов сохраняют свой исходный отступ после любой правки в другом месте карты `[unit: format/]`
- [x] Новые вложенные пункты пишутся тем же отступом, что и первый вложенный пункт файла `[unit: format/]`
- [x] Если в файле ещё нет вложенных пунктов, новые вложенные пункты пишутся с отступом табом `[unit: format/]`
- [x] Текст вне карты (до списка, после него, после JSON-блока) остаётся байт в байт после любой правки карты `[unit: format/]`
- [ ] Текст вне карты на карте не показывается `[вручную: ПК]`
- [x] Дополнительные поля frontmatter (кроме `mindmap`) сохраняются без изменений `[unit: format/]`
- [ ] Текст ноды с Markdown-разметкой (`**жирный**`, `[[ссылка]]`) показывается как есть, обычным текстом с переносами строк `[вручную: ПК]`
- [ ] Файл с пустым списком открывается как пустая карта без ошибки `[unit: format/]` `[вручную: ПК]`

### Slice 3: ID нод, служебный JSON и изменения файла извне

- [x] При сохранении изменений пункту без `^id` молча дописывается новый ID из 6 символов `a-z0-9`, уникальный в пределах файла `[unit: model/]` `[unit: format/]`
- [x] Строки пунктов, у которых ID уже был, при простановке ID не меняются; существующие ID любого вида (например, 4-символьные) сохраняются `[unit: format/]`
- [ ] Открытие и просмотр карты без правок файл не меняет, даже если у пунктов нет ID `[unit: format/]` `[вручную: ПК]`
- [x] JSON-блок записывается в `%% ... %%` в конце файла, по одной ноде на строку `[unit: format/]`
- [x] Служебным считается последний JSON-блок в `%% ... %%` в файле; более ранние блоки — текст вне карты `[unit: format/]`
- [x] В JSON попадают только ноды с собственным состоянием (ручная позиция, свёрнутость, цвет, левая сторона); ноды без него в JSON не пишутся `[unit: format/]`
- [x] Записи JSON для ID, которых больше нет в списке, при сохранении удаляются `[unit: format/]`
- [ ] Файл с повреждённым JSON-блоком открывается как карта с автораскладкой `[unit: format/]` `[вручную: ПК]`
- [ ] При открытии файла с повреждённым JSON-блоком показывается уведомление о том, что раскладка не прочитана `[вручную: ПК]`
- [x] При сохранении повреждённый блок остаётся на прежнем месте как текст вне карты, а новый JSON-блок пишется в конец файла `[unit: format/]`
- [x] Если один `^id` стоит у нескольких пунктов, при сохранении второй и следующие пункты молча получают новые ID `[unit: format/]`
- [x] Состояние из JSON для повторяющегося ID получает нода из первого пункта с этим ID `[unit: format/]`
- [ ] Если файл изменился извне (синхронизация или правка в другом окне), открытая карта перечитывает его и показывает новое содержимое `[вручную: iPad+ПК]`
- [ ] Если файл изменился извне, а в карте есть несохранённые правки, карта перечитывает файл, а несохранённые правки отбрасываются `[вручную: ПК]`
- [ ] Когда несохранённые правки отброшены из-за изменения извне, показывается уведомление «Карта обновлена извне» `[вручную: ПК]`
- [ ] Если файл изменился извне во время ввода текста, перезагрузка выполняется сразу после завершения ввода, а не во время него `[вручную: ПК]`

### Slice 4: Автораскладка и несколько root

Размеры нод `layout/` получает извне; в unit-тестах их задают явно.

- [x] Новой ветке первого уровня сторона назначается по правилу: слева, если правая сторона root выше левой, иначе справа (при равной высоте и у первой ветки — справа) `[unit: layout/]`
- [x] Ветка, созданная в карте, получает сторону в момент создания, и сторона не меняется, когда соседние ветки растут или уменьшаются `[unit: commands/]` `[unit: layout/]`
- [x] Сторона левой ветки записывается в JSON как `"side": "left"`; для правых веток запись о стороне не пишется `[unit: format/]`
- [x] Ветка первого уровня с `^id` стоит на стороне из JSON: слева при `"side": "left"`, иначе справа `[unit: layout/]`
- [x] Ветки первого уровня без `^id` (дописанные в Markdown) получают сторону по правилу высоты в порядке списка при открытии `[unit: layout/]`
- [x] Ветка на левой стороне раскладывается зеркально: её дети стоят слева от родителя `[unit: layout/]`
- [x] Габариты соседних веток не пересекаются при любых размерах нод `[unit: layout/]`
- [ ] Нода не бывает шире 300 px; длинные строки переносятся по словам `[вручную: ПК]`
- [x] Родитель стоит по центру по вертикали относительно общего блока своих детей `[unit: layout/]`
- [ ] Каждый пункт верхнего уровня показан отдельным деревом со своим root `[вручную: ПК]`
- [x] Root без сохранённой позиции (например, дописанный в Markdown) встаёт ниже нижней границы всех остальных деревьев с отступом и не пересекается с ними `[unit: layout/]`
- [ ] Root отличается от остальных нод стилем по умолчанию (например, крупнее шрифт или толще рамка), цвета берутся из CSS-переменных темы Obsidian `[вручную: ПК]`
- [ ] Карта выглядит читаемо в светлой и тёмной теме Obsidian: текст нод контрастен фону (не ниже 4,5:1) `[вручную: ПК]`

### Slice 5: Перемещение по канвасу и зум

- [x] Ведение одним пальцем по пустому месту двигает канвас `[unit: input/]` `[вручную: iPad]`
- [ ] Ведение одним пальцем по канвасу не открывает боковые панели Obsidian и не вызывает навигацию «назад» (гипотеза H2) `[вручную: iPad+iPhone]`
- [x] Щипок двумя пальцами меняет зум; точка карты между пальцами остаётся под пальцами `[unit: viewport/]` `[вручную: iPad]`
- [ ] Прокрутка колесом или двумя пальцами на тачпаде двигает канвас; Shift+колесо — по горизонтали `[вручную: ПК]`
- [x] Ctrl/Cmd+колесо и щипок на тачпаде меняют зум; точка карты под курсором остаётся на месте `[unit: viewport/]` `[вручную: ПК]`
- [ ] Перетаскивание с зажатым пробелом или средней кнопкой мыши двигает канвас `[вручную: ПК]`
- [x] Перетаскивание левой кнопкой мыши по пустому месту канвас не двигает (это жест рамки, Slice 17) `[unit: input/]`
- [x] Зум не опускается ниже 10 % и не поднимается выше 400 % `[unit: viewport/]`
- [x] Перевод координат «экран → карта → экран» возвращает исходную точку при любом зуме и сдвиге `[unit: viewport/]`
- [ ] Apple Pencil двигает канвас и зумит так же, как палец `[вручную: iPad]`
- [ ] Проверка гипотезы H1: карта примерно на 200 нод открывается на iPad, а перемещение и зум идут без рывков, заметных на глаз; результат записан в заметки к срезу `[вручную: iPad]`

### Slice 6: Выделение, добавление и удаление нод

- [ ] Тап или клик по ноде выделяет её, выделение видно на карте `[вручную: iPad+ПК]`
- [ ] Тап или клик по пустому месту снимает выделение `[unit: editor/]` `[вручную: iPad+ПК]`
- [ ] У выделенной ноды видны две кнопки «+»: справа — добавить дочернюю, снизу — добавить соседнюю; зона нажатия каждой кнопки не меньше 44×44 px `[вручную: iPad+ПК]`
- [ ] «+» справа и Tab добавляют ребёнка последним среди детей выделенной ноды `[unit: commands/]`
- [ ] «+» снизу и Enter добавляют соседнюю ноду сразу после выделенной `[unit: commands/]`
- [ ] Enter и «+» снизу у выделенного root создают новый root: в файле он идёт сразу после выделенного, на карте встаёт под его деревом `[unit: commands/]` `[unit: layout/]`
- [ ] Новая нода сразу выделена и открыта на ввод текста `[unit: editor/]` `[вручную: iPad+ПК]`
- [ ] Новая нода, ввод в которой завершён с пустым текстом, удаляется `[unit: editor/]`
- [ ] Существующая нода, у которой стёрли весь текст, остаётся на карте пустой нодой `[unit: editor/]`
- [ ] Delete или Backspace удаляет выделенную ноду вместе со всеми потомками `[unit: commands/]` `[вручную: ПК]`
- [ ] После удаления ветки выделяется предыдущий сосед; если его нет — следующий; если нет и его — родитель `[unit: editor/]`
- [ ] После удаления единственного root ничего не выделено `[unit: editor/]`
- [ ] Delete и Backspace в режиме ввода текста правят текст и ноду не удаляют `[вручную: ПК]`
- [ ] Горячие клавиши карты срабатывают, только когда активен вид карты; в других вкладках Obsidian они не перехватываются `[вручную: ПК]`

### Slice 7: Полноценный ввод текста на всех устройствах

- [ ] F2 открывает ввод текста выделенной ноды `[unit: input/]` `[вручную: ПК]`
- [ ] Enter в режиме ввода переносит строку и не создаёт новую ноду `[вручную: iPad+ПК]`
- [ ] Ctrl/Cmd+Enter завершает ввод и сохраняет текст `[вручную: ПК]`
- [ ] На iPhone и iPad над экранной клавиатурой есть кнопка «Готово», которая завершает ввод `[вручную: iPad+iPhone]`
- [ ] Когда открывается экранная клавиатура, канвас сдвигается так, что редактируемая нода целиком видна над клавиатурой `[unit: viewport/]` `[вручную: iPad+iPhone, обе ориентации]`
- [ ] Если нода уже видна над клавиатурой, канвас не сдвигается `[unit: viewport/]`
- [ ] Многострочный текст показывается в ноде с теми же переносами строк, что и при вводе `[вручную: iPad+ПК]`
- [ ] Esc вне режима ввода снимает выделение `[unit: editor/]`
- [ ] Ввод с аппаратной клавиатуры на iPad работает так же, как на ПК (Tab, Enter, F2, Esc, Ctrl/Cmd+Enter) `[вручную: iPad + клавиатура]`

## Срез 1б: создание карт, undo/redo, навигация

### Slice 8: Новая карта и превращение заметки в карту

- [ ] Команда «Новая карта» в палитре команд создаёт файл карты в папке для новых заметок из настроек Obsidian и открывает его как карту `[вручную: iPad+ПК]`
- [ ] Кнопка «Новая карта» на ленте (ribbon) делает то же, что команда `[вручную: ПК]`
- [ ] Новый файл называется «Без названия.md»; если имя занято — «Без названия 1.md», «Без названия 2.md» и так далее до первого свободного `[вручную: ПК]`
- [ ] Новая карта содержит frontmatter `mindmap: true` и один пустой root, который сразу открыт на ввод текста `[unit: format/]` `[вручную: iPad+ПК]`
- [ ] Команда «Превратить эту заметку в карту» доступна только в обычной заметке без `mindmap: true` `[вручную: ПК]`
- [ ] Превращение добавляет `mindmap: true` во frontmatter и не трогает остальные его поля `[unit: format/]`
- [ ] Превращение создаёт frontmatter, если его не было `[unit: format/]`
- [ ] Превращение дописывает `^id` каждому пункту списка без ID; остальной текст заметки не меняется `[unit: format/]`
- [ ] Если в заметке нет списка, превращение дописывает в конец root с текстом, равным имени заметки без `.md`; весь прежний текст остаётся вне карты без изменений `[unit: format/]`
- [ ] После превращения заметка открывается как карта `[вручную: iPad+ПК]`
- [ ] Для файла с `mindmap: true`, открытого как Markdown, в палитре есть команда «Открыть как карту», которая открывает вид карты `[вручную: iPad+ПК]`
- [ ] В шапке Markdown-вида файла с `mindmap: true` есть кнопка, которая открывает вид карты `[вручную: iPad+ПК]`
- [ ] Для заметок без `mindmap: true` команды и кнопки «Открыть как карту» нет `[вручную: ПК]`

### Slice 9: Добавление root и меню на пустом месте

- [ ] Долгое нажатие на пустом месте открывает меню с пунктом «Добавить ноду» `[unit: input/]` `[вручную: iPad]`
- [ ] Правая кнопка мыши на пустом месте открывает то же меню `[вручную: ПК]`
- [ ] «Добавить ноду» создаёт новый root в точке, где было вызвано меню, и сразу открывает его на ввод текста `[unit: commands/]` `[вручную: iPad+ПК]`
- [ ] Двойной клик по пустому месту создаёт новый root в точке клика и открывает его на ввод `[вручную: ПК]`
- [ ] На пустом канвасе «Добавить ноду» создаёт первый root `[unit: commands/]`
- [ ] Позиция root, созданного из меню или двойным кликом, записывается в JSON абсолютными координатами карты `[unit: format/]`
- [ ] Новый root записывается в файл последним пунктом верхнего уровня `[unit: format/]`
- [ ] Нажатие короче заданной длительности долгого нажатия меню не открывает `[unit: input/]`

## Формы данных (ориентир)

Файл карты:

````markdown
---
mindmap: true
---
- Главная тема ^a1b2c3
	- Подтема ^d4e5f6
	  продолжение многострочного текста
	- Ещё подтема ^g7h8i9
	- Ветка слева ^j0k1l2
- Вторая главная тема ^m3n4o5

%%
```json
{
"version": 1,
"nodes": {
"a1b2c3": {"x": 0, "y": 0, "pinned": true, "collapsed": false, "color": null},
"d4e5f6": {"x": 40, "y": -20, "pinned": true, "collapsed": true, "color": "red"},
"j0k1l2": {"side": "left"}
},
"style": {}
}
```
%%
````

- ID — 6 символов `a-z0-9`; ID другого вида, уже записанные в файле, принимаются как есть.
- `x`, `y` у root — абсолютные координаты карты, у остальных нод — смещение от позиции родителя.
- `color` — одно из `red`, `orange`, `yellow`, `green`, `cyan`, `purple` или `null`.
- `side` пишется только для левых веток первого уровня.
- Поле `style` в MVP пишется пустым и сохраняется как есть.

Модель (ориентир для `model/`):

```
MindMap { roots: Node[] }
Node    { id: NodeId, text: string, children: Node[],
          pinnedPosition?: {x, y}, collapsed: boolean,
          color?: ColorName, side?: 'left' }
```

## Технический контекст

- Проект с нуля (greenfield): пока нет `package.json`, сборки и тестового окружения. Плагин для Obsidian на TypeScript.
- Границы модулей — [.claude/BOUNDARIES.md](../../.claude/BOUNDARIES.md). Пакет `obsidian` импортирует только `obsidian/`. Модули `model/`, `format/`, `commands/`, `layout/`, `viewport/`, `input/`, `editor/` не зависят от фреймворка, и на них приходится основная часть пометок `[unit: …]`.
- Тесты пишутся после кода. Поэтому критерии с пометкой `[unit: …]` сформулированы через входы и выходы чистых функций и модулей: текст файла ↔ дерево, дерево + размеры нод → позиции, команда → новое состояние и обратная команда, последовательность событий указателя → намерение.
- Главный риск — порча файлов пользователя. Для `format/` нужен набор реальных файлов «прочитал — сохранил — сравнил»: табы и пробелы, многострочные пункты, текст вне списка, несколько списков, ручные правки, повреждённый JSON, дублирующиеся ID.
- Оформление берётся только из CSS-переменных темы Obsidian. Отдельного `DESIGN.md` нет, работа над внешним видом — фаза 5.
- Уровень риска: MODERATE.
- Открытый вопрос discovery, не блокирующий спек: на каких моделях iPad и iPhone проверять. Желательно решить к ручной проверке Slice 5 (жесты, H2).

## Решения

Разработчик ответил 2026-10-29: во всех вопросах — вариант (а).

- **ОВ-1.** Картой считается первый непрерывный список после frontmatter, всё остальное — текст вне карты.
- **ОВ-2.** Новый ID — 6 символов `a-z0-9`.
- **ОВ-3.** Новые пункты пишутся отступом, как в файле (по первому вложенному пункту); если вложенных пунктов нет — табом.
- **ОВ-4.** Повреждённый JSON: карта открывается с автораскладкой и уведомлением; старый блок остаётся текстом вне карты, новый пишется в конец файла.
- **ОВ-5.** Повторяющийся `^id`: второй и следующие пункты молча получают новые ID; состояние из JSON достаётся первому.
- **ОВ-6.** При изменении извне побеждает внешняя версия; если идёт ввод, перезагрузка ждёт его завершения; показывается уведомление «Карта обновлена извне»; история undo очищается.
- **ОВ-7.** Сторона ветки назначается при создании и хранится в JSON (`"side": "left"` только у левых); ветки, дописанные в Markdown (без `^id`), получают сторону по правилу при открытии.

- **ОВ-15.** Возврат из Markdown: команда «Открыть как карту» и кнопка в шапке Markdown-вида.
- **ОВ-16.** Стрелки ← → работают по экрану, на левой стороне зеркально; ↑ ↓ — соседи; без выделения стрелка выделяет первый root.

- **ОВ-21.** Вставка — последним ребёнком выделенной ноды, без выделения — новым root; обычный текст — по ноде на каждую непустую строку; дубликат — соседом после оригинала, с цветом и свёрнутостью.
